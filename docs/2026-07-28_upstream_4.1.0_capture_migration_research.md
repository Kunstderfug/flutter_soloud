# Upstream `flutter_soloud` 4.1.0 capture and scheduling migration audit

Date: 2026-07-28

Repositories inspected:

- Official upstream tag [`v4.1.0`](https://github.com/alnitak/flutter_soloud/tree/v4.1.0), annotated tag object `1382a0f0d7fa574ce583ae7f8f0cca2af8995fe9`, commit `dd7e650e509004d2e4fa3d264372454e8d34913c`.
- Local fork branch `features_capture`, commit `5b2e39f9d64cb909674a0d8adb04f7453dc63083`.
- GPhil checkout at `/Volumes/DRIVE/DEV/gphil-flutter`, commit `35370331451a9f44e0fb2fb9f7d010f195d23230`.

## Decision

We should adopt upstream 4.1.0, but **not by replacing the fork with the published package yet**. Upstream's new capture feature records the SoLoud **master output mix**. GPhil's custom capture records a selected miniaudio **input/microphone device** and exposes synchronization and recording diagnostics that upstream does not have. These are complementary features, not competing implementations.

The safe path is a controlled integration branch based on upstream `v4.1.0`, with the remaining GPhil-specific patches replayed and tested. Drop the now-upstream loop implementation and migrate the custom relative `playDelayed` call to upstream scheduling. Keep the microphone-capture patch set, WavPack wiring, and mixing-bus sample-rate fix for now.

## What upstream 4.1.0 adds

The official [4.1.0 changelog](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/CHANGELOG.md#L1-L21) lists master-mixer capture, isolate-safe capture, native loop endpoints, `playClocked`, and absolute engine-time scheduling. The tag requires Dart 3.11 and Flutter 3.41 ([`pubspec.yaml`](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/pubspec.yaml#L1-L27)).

### Master mixer output capture

`SoLoud.startMixerOutputStream()` returns a `Stream<Uint8List>` and accepts PCM F32LE/S8/S16LE/S32LE, Opus, Vorbis, FLAC, or WAV, explicit sample-rate/channel values (or `-1` to follow the engine), a circular-buffer size, a notification threshold, and fixed-size PCM chunking. It is still marked `@experimental`. WAV callers must replace the initial 44-byte placeholder header after stopping ([public API](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud.dart#L849-L928), [formats](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/enums.dart#L441-L530)).

The native hook runs immediately after `soloud->mix()` fills the output buffer, so this is the rendered master output, including routed buses and output processing—not an input device ([miniaudio callback](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/soloud/src/backend/miniaudio/soloud_miniaudio.cpp#L212-L247)). The official README separately describes master-output capture and recommends another package for input recording ([README](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/README.md#L15-L43)).

`SoLoudIsolate` can own the output stream from a worker isolate after the engine is initialized on the main isolate. It intentionally does not expose init/deinit, loading, playback, filters, or playback events ([isolate API](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud_isolate.dart#L13-L107)).

Important operational details:

- Starting twice through the same manager returns the existing stream rather than reconfiguring it ([stream manager](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/mixer_output_stream_manager.dart#L41-L99)).
- Stopping synchronously flushes data below the notification threshold before closing the stream ([stream manager](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/mixer_output_stream_manager.dart#L115-L161)).
- Static inspection did not find a generic sample-rate or channel-count converter between the engine's `pOutput` and `MixerOutput`; `onAudioData` interprets the engine buffer using the requested channel count. Start with `sampleRate: -1, channels: -1` and treat custom values as requiring an upstream test/confirmation ([capture start](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/mixeroutput/mixer_output.cpp#L25-L145), [audio callback](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/mixeroutput/mixer_output.cpp#L195-L259)).
- If the native circular output buffer fills, the implementation advances the read position and drops the oldest bytes; it does not expose a drop counter ([native buffer handling](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/mixeroutput/mixer_output.cpp#L195-L259)). At 48 kHz stereo F32, the default 1 MiB buffer holds about 2.73 seconds.
- On native platforms, compressed output is encoded on a background thread. The intermediate PCM queue is unbounded, so callers should still test memory behavior during long captures or sustained encoder backpressure ([queue implementation](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/mixeroutput/pcm_queue.h#L11-L35), [encoder loop](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/mixeroutput/mixer_output.cpp#L339-L369)).
- Upstream says web must run with `--wasm` or a server configured with COOP/COEP headers because the audio worker uses `SharedArrayBuffer` ([changelog](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/CHANGELOG.md#L10-L13)). GPhil's helper already builds/runs web with `--wasm`, but the deployed Netlify path still needs a production smoke test.

### Loop endpoints

Upstream merged GPhil's native loop-end work through [PR #499](https://github.com/alnitak/flutter_soloud/pull/499). The public API preserves the same half-open `[start, end)` model:

- `loopingEndAt` on `play`, `play3d`, and bus variants.
- `getLoopEndPoint` and `setLoopEndPoint`.
- `null` means the source's natural end.
- Live changes take effect at the next source refill, potentially after up to 512 already-decoded source frames plus backend latency ([loop API](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud.dart#L2427-L2482)).

The local and upstream loop helper/tests match at a functional level; the final upstream review changed only attribution/copyright around the loop patch. Upstream also regenerated web artifacts and supports bounded loop endpoints on web, while the local `Preserve legacy web playback` commit deliberately throws when a bounded web loop is requested. Therefore, local commits `5cc9cc0` and `5b2e39f` should be dropped in favor of upstream.

### Clocked and scheduled playback

`playClocked`/`play3dClocked` use an application-provided, monotonically increasing physics time. The first call anchors that clock about two output buffers ahead; calls that go backward or jump by more than about two seconds re-anchor. This gives sample-accurate spacing but adds a constant scheduling latency and does not support paused/looping parameters ([API and semantics](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud.dart#L1839-L1988), [PR #505](https://github.com/alnitak/flutter_soloud/pull/505)).

`getEngineTime` plus `playScheduled`, `stopScheduled`, and `fadeScheduled` use absolute engine time with no two-second window. `playScheduled` can atomically attach a duration; scheduled stops are sample-accurate, and `fadeScheduled` can stop after fading ([API and semantics](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud.dart#L1990-L2145), [PR #509](https://github.com/alnitak/flutter_soloud/pull/509)).

GPhil currently calls the fork-only relative API `playDelayed(source, delay: ...)` in `lib/services/audio/soloud_metronome_audio_output.dart:23-42`. The closest upstream replacement is:

```dart
final atTime = player.getEngineTime() + delay;
final handle = player.playScheduled(source, atTime, volume: volume);
```

That lets us drop local commit `7380d53`. `playClocked` is also suitable if the metronome scheduler already owns one monotonic score/physics timeline and accepts its deliberate two-buffer latency.

## Capture comparison

| Capability | Local `features_capture` | Upstream 4.1.0 |
|---|---|---|
| Signal recorded | Selected miniaudio input/microphone | Post-mix SoLoud master output |
| Primary API | `startCapture`, `startCaptureAndPlay`, `stopCapture`, `cancelCapture` | `startMixerOutputStream`, `stopMixerOutputStream` |
| Delivery | Native IEEE-float WAV file plus optional sidecar | Dart byte stream; caller stores/processes it |
| Encodings | WAV safety file; optional FLAC or WavPack mirror | PCM F32/S8/S16/S32, Opus, Vorbis, FLAC, WAV |
| Input device selection | `CaptureDevice` enumeration and selection | None; no input device is involved |
| Input gain | Native dB gain | None; signal is already the rendered output |
| Capture/play coordination | One native `startCaptureAndPlay` path | Output stream starts independently; playback can use scheduled APIs |
| Clock/timeline data | Session, capture-start, first-buffer, playback-start, stop host timestamps and input-frame positions | No capture-specific host clock/frame snapshot |
| Live levels | Peak, RMS, peak-since-read, held peak, frame count | No mixer-capture level snapshot API |
| Loss diagnostics | Reports writer overflow, inserted-silence frames, writer failure, mirror success/frame count | Oldest circular-buffer bytes are dropped on overflow; no public drop count |
| Web | Explicitly not implemented in the local bindings | Supported with upstream's web/WASM constraints |

Local evidence:

- The public input-capture API, capture device selection, gain, clock snapshots, level snapshots, and stop diagnostics are in [`lib/src/soloud.dart`](https://github.com/Kunstderfug/flutter_soloud/blob/5b2e39f9d64cb909674a0d8adb04f7453dc63083/lib/src/soloud.dart#L458-L639) and the result models in [`lib/src/capture/soloud_capture.dart`](https://github.com/Kunstderfug/flutter_soloud/blob/5b2e39f9d64cb909674a0d8adb04f7453dc63083/lib/src/capture/soloud_capture.dart#L1-L319).
- The native callback applies input gain, computes levels, writes through a two-second-or-larger ring, reports overflow, and inserts silence to preserve recording duration ([`src/player.cpp`](https://github.com/Kunstderfug/flutter_soloud/blob/5b2e39f9d64cb909674a0d8adb04f7453dc63083/src/player.cpp#L661-L902)).
- The local web binding returns `notImplemented` for these input APIs ([web bindings](https://github.com/Kunstderfug/flutter_soloud/blob/5b2e39f9d64cb909674a0d8adb04f7453dc63083/lib/src/bindings/bindings_player_web.dart#L179-L249)).

GPhil uses the missing local APIs directly:

- `lib/services/recording/user_audio_recorder.dart:125-269` defines its backend around `CaptureDevice`, `startCapture`, `startCaptureAndPlay`, capture clocks, and capture levels.
- The normal microphone path starts a 48 kHz stereo capture with gain/device/mirror options at `user_audio_recorder.dart:525-573`.
- Coordinated microphone recording plus accompaniment playback calls `startCaptureAndPlay` at `user_audio_recorder.dart:644-731`.
- Stop processing consumes the custom stop diagnostics at `user_audio_recorder.dart:783-813`.

Consequently, replacing the fork with upstream 4.1.0 would fail to compile and would remove behavior required for recording/replay alignment. Master-output capture cannot substitute for this microphone path.

## Other fork dependencies that prevent a package-only switch

1. **Mixing-bus sample-rate synchronization is still fork-only.** Local commit `ed619d0` sets each bus's `mBaseSamplerate` to the engine backend sample rate at creation and before `playOnEngine`. Upstream 4.1.0 `BusData` still only constructs the bus and filters ([upstream `BusData`](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/src/filters/filters.h#L73-L88)). GPhil initializes native audio at 48 kHz (`gphil-flutter/lib/controllers/audio_controller.dart:16-21`), so keep this patch and its regression test.
2. **WavPack remains GPhil-specific.** The microphone capture can create a WavPack sidecar, and GPhil's macOS Podfile explicitly adds the fork's WavPack headers/library (`macos/Podfile:109-133`). Upstream 4.1.0 has no WavPack capture format or `src/wavpack` tree.
3. **GPhil compiles flutter_soloud implementation sources directly.** Its dependency is a local path (`gphil-flutter/pubspec.yaml:21-22`); Windows builds include `../flutter_soloud/src/src.cmake` and filter sources (`windows/runner/CMakeLists.txt:47-78`); Apple export bridges include filter and SoLoud headers through `../../../flutter_soloud` (`ios/Runner/ExportFxBridge.mm:1-8`, with a parallel macOS bridge). A pub-only dependency change needs a separate native-export decoupling project.
4. **Android init behavior changes.** Upstream 4.0.12+ adds `lowLatency` and `AndroidAAudioAttributes`. `lowLatency: false` makes Android output recordable by system capture at the cost of latency ([upstream init docs](https://github.com/alnitak/flutter_soloud/blob/v4.1.0/lib/src/soloud.dart#L326-L401)). This does not replace microphone capture, but the chosen profile should be explicit in GPhil rather than inherited accidentally.

## Recommended integration plan

1. Create an integration branch from official `v4.1.0`, rather than resolving a large merge while retaining duplicate upstream commits.
2. Replay the microphone-capture commits `6f35772`, `33e77eb`, `1ccca16`, `e080e97`, `08b8021`, `0c99d39`, `f4e6eae`, plus the Apple WavPack wiring in `2110b88`, adapting them to the new bindings/callback lifecycle.
3. Replay `ed619d0` (mixing-bus sample-rate sync).
4. Do not replay `5cc9cc0` or `5b2e39f`; use upstream's reviewed native/web loop endpoint implementation.
5. Replace GPhil's `playDelayed` call with `getEngineTime() + playScheduled`, then omit `7380d53`.
6. Keep upstream's mixer-output capture as a separate optional facility—for mixdown, streaming, diagnostics, and capture-based timing tests—not as the user-microphone recorder.
7. Only consider removing the fork after microphone capture is moved into a separate maintained plugin/native service and GPhil's export bridges stop compiling the local flutter_soloud source tree directly.

## Required verification before landing

- Run flutter_soloud analysis/unit/native tests and upstream mixer-output, loop, clocked-play, and scheduled-play integration tests.
- Add native integration coverage for custom microphone start/stop/cancel, selected input device, gain, 48 kHz stereo format, level snapshots, clock snapshots, coordinated capture/play start, FLAC/WavPack mirrors, and overflow/silence diagnostics.
- Verify deinit/hot restart while either capture type is active. Upstream 4.1.0 changes callback teardown specifically to prevent callbacks after native callables are closed.
- Verify 48 kHz bus playback/filter behavior to protect `ed619d0`.
- Migrate and test the GPhil metronome against `playScheduled`, including cancellation before start and start-observer behavior.
- Build and smoke-test iOS/macOS through both relevant CocoaPods/SPM paths, Android (including the selected `lowLatency` profile), Windows, Linux, and deployed web/WASM.
- Perform a long-running output-capture soak test with intentionally slow consumers to characterize circular-buffer drops and compressed-encoder memory growth before using it for irreplaceable recordings.
